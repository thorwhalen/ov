ov.analysis.run

The analysis orchestrator – resolve, order, run analyzers, merge into the run.

run_analysis is what ov.analyze() calls. It selects analyzers by lens, orders them by their requires/produces dependencies, runs each over an AnalysisContext, and merges every AnalyzerOutput back into the CaptureRun (findings, endpoints, tech, run fields). It is model-free and idempotent: it clears prior analysis output before re-running so a run can be re-analyzed.

ov.analysis.run.merge_output(run: CaptureRun, out: AnalyzerOutput) → None[source]

Merge one analyzer’s output into the run (findings, endpoints, tech, fields).

Tech dedupes by name: confidence takes the max, provenance and categories union (so a package seen both as a recovered dependency and by framework/bundler signature keeps both category identities), and a missing version is filled from any analyzer that supplies one (source-map versions are the top provenance rank, so they must not be lost to an earlier versionless detection).

ov.analysis.run.run_analysis(run: CaptureRun | str, *, lenses: Iterable[str] = ('ux', 'arch'), store: Any = None, config: OvConfig | None = None) → dict[str, Any][source]

Run the deterministic analyzers for lenses over a run; return per-analyzer summaries.

run may be a CaptureRun or a run id (loaded from store). The run is mutated in place (findings/api_surface/fingerprint/rendering_model/…) and persisted; an analysis blob is also stored.
