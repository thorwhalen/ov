ov.agents.definitions

SSOT: which ov skills become which agents (role, lens, model routing).

The extras a skill needs to become an agent — model, tool allowlist, return contract, MCP exposure — live in each skill’s additive coact: frontmatter block (coact reads them during COMPLETE). This module records only the ov-side mapping coact cannot infer: which skill plays which role in the study pipeline and, for analysts, which analysis lens it carries.

Everything here is data. Add an agent by adding a row — no dispatcher to edit (open-closed). This mirrors ov’s other registries (probes / analyzers / report sections): a capability is a registered piece of data, never a branch in a switch.

class ov.agents.definitions.AgentSpec(name: str, role: str, skill: str, lens: str | None = None, default_model: str = 'sonnet')[source]

One ov agent: its name, role, source skill, optional lens, default model.

>>> AgentSpec("ov-analyze-ux", "analyst", "ov-analyze-ux", "ux").lens
'ux'
ov.agents.definitions.OV_AGENTS: dict[str, AgentSpec] = {'arch-analyst': AgentSpec(name='ov-analyze-arch', role='analyst', skill='ov-analyze-arch', lens='arch', default_model='opus'), 'operator': AgentSpec(name='ov-operate', role='operator', skill='ov-operate', lens=None, default_model='haiku'), 'orchestrator': AgentSpec(name='study-web-app', role='orchestrator', skill='study-web-app', lens=None, default_model='opus'), 'ux-analyst': AgentSpec(name='ov-analyze-ux', role='analyst', skill='ov-analyze-ux', lens='ux', default_model='sonnet')}

The ov agent registry (role key -> spec) — the headline of Phase 4. Model defaults follow the spec’s §10 cost gate (Opus for design/planning judgment, Sonnet for grounded UX narrative, Haiku for the throughput-bound driver).
